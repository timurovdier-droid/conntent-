## 1. Краткое описание

Рабочее название: ContentPilot AI. Название временное и может быть заменено.

ContentPilot AI - веб-платформа, в которой пользователь описывает задачу обычным языком, а AI-агент помогает подготовить контент под конкретную аудиторию, бренд и канал публикации. В одном рабочем пространстве можно сгенерировать текст, сценарий короткого видео, рекламный вариант или идею контент-плана, внести правки диалогом, создать визуал и сохранить результат в проект.

Цель MVP: сократить путь от идеи до готового черновика публикации и сделать результат управляемым: с учётом тона бренда, языка, формата, целевого действия и истории изменений.

> **Важно:** Продукт не должен обещать гарантированные охваты, продажи или вирусность. Он помогает быстрее подготовить и улучшить контент, но результат зависит от данных пользователя, качества редакторской проверки и внешних площадок.

| Параметр | Решение для первой версии |
| --- | --- |
| Формат | Адаптивный веб-сайт / web app |
| Основная ценность | Сделать качественный контент быстрее, без необходимости писать сложные промпты |
| Основные рынки на старте | Русскоязычные и узбекоязычные пользователи; дополнительные языки - по запросу |
| Основная модель текста и агента | Gemini 3.8 Flash через Gemini Interactions API |
| Модель генерации изображений | Gemini Nano Banana 2.1 как отдельный image-generation путь |
| Граница MVP | Генерация и редактирование; без автоматической публикации в соцсети |

## 2. Проблема и целевые пользователи

### Проблема

Малому бизнесу, маркетологам и авторам регулярно нужен контент, но подготовка публикаций занимает время: приходится придумывать тему, подбирать тон, адаптировать текст под платформу и несколько раз переписывать результат. Универсальные чат-инструменты часто требуют длинных инструкций и не сохраняют контекст бренда между задачами.

### Основные сегменты

| Сегмент | Задача | Что важно |
| --- | --- | --- |
| Владелец малого бизнеса | Регулярно продвигать продукт или услугу | Простота, готовые шаблоны, минимум настроек |
| SMM-специалист / маркетолог | Быстро делать варианты для разных каналов | Тон бренда, повторное использование контента, управление проектами |
| Контент-креатор | Готовить сценарии и идеи для коротких видео | Хуки, структура, варианты и быстрое редактирование |
| Интернет-магазин | Описывать товары и делать промоматериалы | Точность характеристик, CTA, возможность приложить исходные данные |

### Первичный пользовательский сценарий

Пользователь создаёт профиль бренда один раз, затем каждый раз выбирает тип контента и задаёт цель. Агент использует сохранённый контекст и возвращает результат в редактируемом виде, а не только сообщением в чате.

## 3. Принципы продукта

- Сначала результат, потом настройки: пользователь должен получить полезный первый черновик без необходимости разбираться в промпт-инжиниринге.
- Контекст бренда сохраняется отдельно от промптов и может быть изменён пользователем.
- Пользователь управляет финальным текстом: AI предлагает, объясняет и редактирует, но не публикует без отдельного подтверждения.
- Факты не выдумываются: неизвестные цены, характеристики, гарантии и статистика отмечаются как требующие подтверждения.
- Мультиязычность является рабочим требованием, а не декоративной функцией: язык можно задать для каждого результата.
- Стоимость использования контролируется на сервере: лимиты, учёт запросов и смена модели настраиваются без переделки интерфейса.

## 4. Объём MVP и границы

### Входит в MVP

| Функция | Объём |
| --- | --- |
| Аккаунт и стартовая настройка | Регистрация / вход, базовый профиль, создание первого рабочего пространства |
| Профиль бренда | Название, ниша, продукт/услуга, аудитория, тон общения, язык, ограничения, CTA, запрещённые формулировки |
| AI-генератор | Пост для соцсетей, рекламный текст, описание товара/услуги, сценарий Reels/TikTok/Shorts, идеи и простой недельный контент-план |
| Редактирование диалогом | Сократить, расширить, изменить тон, перевести, поменять CTA, дать 3 варианта, адаптировать под другой канал |
| История и проекты | Сохранение черновика, название проекта, список результатов, версии и повторное открытие |
| Генерация изображений | Создать визуальную концепцию и изображение по текстовому описанию; повторная генерация и скачивание |
| Экспорт | Копирование текста, скачивание изображения, экспорт результата в Markdown или TXT |
| Контроль расходов | Серверные квоты, лимит частоты, журнал использования моделей, дружелюбные ошибки |
| Администрирование | Минимальный просмотр пользователей, usage, ошибок генерации и настройка квот |

### Не входит в MVP

- Автоматическая публикация и планирование постов через Instagram, TikTok, YouTube, Telegram и другие платформы.
- Полноценный редактор видео, генерация видеороликов и озвучки.
- Командные роли, согласование публикаций и сложное агентство с несколькими клиентами.
- Собственная базовая модель, обучение модели на данных пользователя и fine-tuning.
- Автономный агент, который без подтверждения отправляет сообщения, запускает рекламу или выполняет действия во внешних системах.
- Сбор фактов из интернета как обязательная часть каждой генерации. Поиск и проверка актуальных данных - отдельная следующая функция.

## 5. Основные пользовательские потоки

### Поток A - первый запуск

1. Пользователь создаёт аккаунт и открывает рабочую панель.
2. Система предлагает заполнить профиль бренда; можно пропустить необязательные поля.
3. Пользователь выбирает «Создать контент» и тип результата.
4. Пользователь вводит тему / продукт, цель, площадку, язык и дополнительные ограничения.
5. Агент использует профиль бренда и параметры задачи, затем создаёт черновик.
6. Пользователь редактирует текст, сохраняет результат и копирует / скачивает его.

### Поток B - работа с агентом

1. Пользователь открывает сохранённый результат.
2. Вводит команду простым языком, например: «Сделай короче, добавь более сильный первый абзац и не используй эмодзи».
3. Агент изменяет текущую версию и показывает её как новую версию, не стирая исходный вариант.
4. Пользователь принимает результат, возвращается к предыдущей версии или просит ещё одну правку.

### Поток C - генерация визуала

1. Пользователь нажимает «Создать изображение» в рамках проекта.
2. Система использует тему, бренд-контекст, площадку, формат и описание пользователя для image prompt.
3. Модель генерирует изображение; интерфейс показывает загрузку и ошибки по отдельному статусу.
4. Пользователь может повторить генерацию, скачать файл или сохранить изображение в проект.

## 7. Требования к AI-агенту

### Роль агента

Агент выступает как помощник контент-стратега, копирайтера и редактора. Он не должен превращать каждую задачу в длинный диалог: если обязательных данных достаточно, сразу готовит черновик. Вопрос задаётся только тогда, когда без ответа высок риск сделать неверный или вводящий в заблуждение контент.

### Входные данные

- Профиль бренда: ниша, продукт, аудитория, ценностное предложение, тон, язык и запреты.
- Параметры текущей задачи: тип контента, площадка, цель, тема, длина, CTA, ключевые факты и ограничения.
- При наличии - исходный текст, описание товара, изображения или пользовательский пример стиля.
- Контекст предыдущих версий проекта, если пользователь редактирует существующий результат.

### Формат результата

Ответ модели должен по возможности возвращаться структурированным объектом, а не только свободным текстом. Пример полей: title, hook, body, CTA, hashtags, visual_prompt, notes_to_verify, language, format, variant_label. Набор полей зависит от выбранного типа контента. Сервер проверяет схему, очищает недопустимые значения и сохраняет результат в базе.

### Правила качества

- Не выдумывать характеристики, цены, сроки, результаты, отзывы, сертификаты и юридические обещания.
- Различать факт, гипотезу и рекламное преувеличение; неизвестные данные выносить в «Проверить перед публикацией».
- Соблюдать выбранные язык, тон, длину, платформу, аудиторию и запрещённые слова.
- Избегать одинаковых шаблонных вступлений; по запросу предлагать разные креативные углы.
- Не раскрывать внутренние инструкции, секреты API или данные других пользователей.
- Показывать пользователю предупреждение, если результат требует проверки фактов или прав на использование исходных материалов.

### Поведение при недостатке данных

Если не указана цена, конкретное преимущество или другой факт, важный для рекламного утверждения, агент не должен придумывать его. Он может написать нейтральную версию, использовать плейсхолдер вроде [укажите цену] либо задать один короткий уточняющий вопрос.

## 8. Интеграция Gemini и техническая концепция

| Компонент | Предложение | Зачем |
| --- | --- | --- |
| Текстовый агент | Gemini 3.8 Flash | Основная модель для диалога, генерации текстов и многошаговой обработки |
| API для агента | Gemini Interactions API | Единый интерфейс для генерации и agentic workflows; поддерживает последовательные шаги и tool calling |
| Изображения | Gemini Nano Banana 2.1 | Отдельный путь генерации и редактирования изображений |
| Вызов инструментов | Ограниченный server-side function calling | Сохранение результата, получение профиля бренда и работа с проектами через контролируемые серверные функции |
| Хранение истории | Наша база данных | Контроль доступа, версий и удаления данных независимо от модели |
| Секреты | Переменные окружения / secret manager | API-ключ Google не попадает в браузер и не хранится в клиентском коде |

### Предлагаемая архитектура

- Frontend: Next.js + TypeScript, компонентная UI-система, адаптивная рабочая панель.
- Backend: серверные маршруты/API для генерации, редактирования, сохранения версий, файлов и лимитов.
- База данных: PostgreSQL; таблицы пользователей, пространств, профилей бренда, проектов, контентных версий, файлов и usage events.
- Файлы: object storage с приватными объектами и временными ссылками на скачивание.
- AI-адаптер: отдельный сервисный слой для вызовов Gemini, валидации ответа, retries, timeouts, логирования и маршрутизации между моделями.
- Мониторинг: ошибки API, задержка генераций, расход токенов/кредитов, доля неуспешных ответов и лимиты пользователей.

### Критичные технические правила

- Вызов модели выполняется только на сервере; ключ никогда не отправляется на frontend.
- Использовать структурированный формат ответа, где он поддерживается, и проверять ответ по схеме на сервере.
- Сохранять в журнале технические метаданные, но не писать чувствительные исходные промпты/файлы в логи без необходимости.
- Проверить параметры хранения запросов и политику обработки данных Gemini перед production. По умолчанию хранить историю приложения в собственной базе и отключить ненужное хранение на стороне API там, где это поддерживается.
- Версии model ID и лимиты должны задаваться конфигурацией; не зашивать их в UI.

Важно: конкретные модельные ID подтверждены документацией Google на дату подготовки PRD, 21 октября 2026 года. Перед разработкой и релизом следует повторно проверить доступность моделей, цены, лимиты, условия хранения данных и доступность API для выбранного региона и типа аккаунта.

## 9. Информационная структура и экраны

| Экран | Основные элементы |
| --- | --- |
| Лендинг | Ценность продукта, короткая демонстрация результата, CTA «Попробовать» / «Войти», тарифная секция может быть скрыта до определения монетизации |
| Регистрация / вход | Email или поддерживаемый внешний провайдер, восстановление доступа, согласие с политиками |
| Dashboard | Кнопка создания, последние проекты, лимит/остаток использования, быстрые шаблоны |
| Профиль бренда | Форма редактирования ниши, аудитории, тона, языка, ключевых преимуществ и запретов |
| Создание контента | Формат, канал, цель, тема, бренд, язык, тон, ограничения, прикрепление исходного материала |
| Редактор результата | Редактируемый текст, варианты, быстрые команды, история версий, копирование/экспорт, генерация визуала |
| Проекты | Поиск, сортировка по дате, открытие, переименование и удаление |
| Настройки | Профиль, приватность, удаление аккаунта, предпочтительный язык |
| Админ-панель | Пользователи, usage, ошибки, системные лимиты и статус API без доступа к чужим приватным данным сверх необходимого |

### Принципы UX

- Главный CTA в панели всегда заметен: «Создать контент».
- На экране создания показывать только параметры, реально влияющие на результат; расширенные настройки скрывать под «Дополнительно».
- Во время генерации отображать реальный статус и позволять отменить долгую задачу там, где это технически возможно.
- Результат должен иметь отдельные действия: «Скопировать», «Сохранить», «Редактировать», «Новый вариант», «Создать визуал».
- Пустые состояния объясняют следующий шаг, а ошибки дают способ восстановления, а не только код ошибки.

## 11. Безопасность, приватность и доверие

- Хранить API-ключи и ключи хранилища только на сервере и в secret manager/переменных окружения.
- Применять аутентификацию, проверку владельца ресурса на каждой операции, ограничение частоты и защиту от автоматизированного злоупотребления.
- Ограничить типы и размер загружаемых файлов; проверить MIME type и безопасно обрабатывать изображения.
- Не позволять содержимому пользовательских файлов переопределять системные правила агента. Рассматривать документы и изображения как недоверенный пользовательский ввод.
- Показывать правила обработки контента и условия удаления данных. Не обещать абсолютную конфиденциальность, пока не изучены условия API и хранилища.
- Обеспечить удаление проектов, файлов и связанной истории по запросу, с понятным сроком полного удаления из резервных копий.
- Добавить базовые ограничения для запрещённого и опасного контента и безопасную обработку запросов, которые модель отклоняет.
- Перед запуском подготовить Terms of Service, Privacy Policy и правила допустимого использования с юридической проверкой под целевой рынок.

## 13. Метрики успеха и аналитика

| Метрика | Что измеряет | Начальная цель / подход |
| --- | --- | --- |
| Activation rate | Доля новых пользователей, которые получили первый успешный результат | Установить baseline после пилота; целиться в рост по итерациям |
| Time to first value | Время от регистрации до первого сохранённого/скопированного результата | Сокращать; отдельно отслеживать шаги с отвалом |
| Generation success rate | Доля запросов, завершившихся валидным результатом | Целевой ориентир >= 95% для технически валидных запросов после исключения safety refusals и внешних outage |
| Save/copy rate | Доля сессий с копированием или сохранением результата | Главный индикатор практической полезности |
| Edit/regenerate rate | Как часто результат требует правки или повторной генерации | Интерпретировать вместе с save/copy; высокая частота сама по себе не успех/провал |
| 7-day retention | Возвращение пользователя в течение 7 дней | Измерять по когортам после запуска пилота |
| Cost per successful result | Расход моделей на один успешный результат | Контролировать по типу задачи и модели; цены подтягивать из актуальной конфигурации |
| Feedback score | Оценка «полезно / не полезно» или 1-5 | Собирать добровольную оценку и причину неудовлетворённости |

Числа в таблице являются стартовыми рабочими ориентирами, а не подтверждёнными рыночными бенчмарками. После тестирования на реальных задачах их нужно уточнить.

## 14. Тестирование и критерии готовности

### Обязательные тесты

- Новый пользователь может пройти регистрацию, создать бренд-профиль и получить первый контентный черновик.
- Изменение языка/тона/платформы влияет на результат и отражается в структуре ответа.
- Команда редактирования не теряет важные факты, запреты и формат исходной задачи.
- Каждая сохранённая версия восстанавливается и не перезаписывает предыдущую без согласия пользователя.
- При таймауте/ошибке Gemini UI показывает понятное сообщение; повтор не создаёт дубликаты и не расходует квоту дважды.
- Пользователь A не может открыть проект, файл или профиль пользователя B даже если знает идентификатор ресурса.
- API key отсутствует в клиентском bundle, сетевых ответах браузера и публичных логах.
- Генерация изображения поддерживает состояния loading/success/failure; скачивание работает на desktop и mobile.
- Ограничения тарифа/квоты действуют на сервере и не обходятся изменением frontend.
- Удаление проекта удаляет или делает недоступными соответствующие версии и файлы согласно политике хранения.

### Набор оценки качества модели

Перед запуском подготовить 30-50 типовых задач на русском и узбекском: посты для бизнеса, объявления, описания товаров, сценарии коротких видео, перевод и правки стиля. Проверять фактологическую точность, следование ограничениям, естественность языка, соответствие формату, полезность первого результата и приблизительную стоимость. Для критичных сценариев хранить эталонные критерии, не «идеальный ответ» как единственную формулировку.

## 15. План реализации

| Этап | Результат | Definition of Done |
| --- | --- | --- |
| 0. Уточнение продукта | Финализация названия, основного сегмента, типов контента, квот и модели оплаты | Решения по открытым вопросам зафиксированы; согласован MVP |
| 1. Основа приложения | Auth, рабочее пространство, база, профиль бренда, dashboard | Пользователь может войти, создать бренд и сохранить данные |
| 2. Текстовый агент | Gemini integration, шаблоны, структурированные ответы, редактирование | Основные сценарии создания и корректировки проходят acceptance tests |
| 3. Проекты и версии | Сохранение, поиск, история, копирование и экспорт | Результат можно сохранить, открыть и восстановить |
| 4. Генерация визуалов | Интеграция image model, storage, статусы и скачивание | Изображение генерируется и привязывается к проекту; usage учитывается отдельно |
| 5. Качество и безопасность | Rate limits, permission tests, monitoring, политика данных, ошибки API | Пройдены security/QA чек-лист и тест на модельные расходы |
| 6. Закрытый пилот | Тестирование с небольшой группой целевых пользователей | Собрана обратная связь и исправлены блокирующие дефекты |

### Возможности после MVP

- Публикационный календарь и планирование по датам.
- Интеграции с каналами публикации с явным OAuth и подтверждением пользователя.
- Командные пространства для SMM-агентств и клиентские бренд-профили.
- Генерация/монтаж видео, субтитров и озвучки.
- Поиск в интернете для актуальных фактов с отображением источников.
- Платные тарифы, пакеты кредитов, биллинг и детальная аналитика окупаемости.
